    40→## Gotchas (verified the hard way)
    41→
    42→1. **The exported-`DATABASE_URL` trap.** A shell-exported absolute
    43→   `DATABASE_URL` overrides the repo `.env` for the Prisma CLI **and** the
    44→   Next runtime — the server silently opens a foreign database file (the
    45→   historical 12/30 smoke failure). `scripts/smoke-test.sh` and
    46→   `playwright.config.ts` PIN their own `DATABASE_URL` per command; keep that
    47→   discipline in every script that boots a server or runs Prisma.
    48→2. **Relative `file:` URLs are schema-anchored.** `DATABASE_URL` in `.env` is
    49→   `file:../db/custom.db`, which resolves against `prisma/schema.prisma` for
    50→   the CLI and against the same anchor at runtime via `src/lib/db-path.ts`
    51→   (unit-tested by `tests/db-path.test.ts`). One string → one file:
    52→   `<repo>/db/custom.db`. The `db/` folder sits at the repo root and is
    53→   git-ignored (`db/*.db`).
    54→3. **Tailwind v4 is CSS-first.** Tokens live in `src/app/globals.css` under
    55→   `@theme` — never add a `tailwind.config.*` or the `@config` bridge. Two
    56→   v4 traps are load-bearing here: theme vars must be FULL color values
    57→   (bare HSL triplets resolve to transparent), and `button,
    58→   [role="button"] { cursor: pointer }` is set in the base layer because v4's
    59→   preflight sets no pointer. See `docs/Tailwind-V4-Validation-Report.md`.
    60→4. **v4 serializes `bg-white/10`-style colors through `oklab()`** —
    61→   rendering-identical to the reference's rgba strings but
    62→   computed-string-different. E2E assertions accept either spelling (see the
    63→   mobile-navigation spec comments); never "fix" the CSS to chase byte-parity.
    64→5. **The UI font is GOOGLE's "Vend Sans"** (variable wght 300-700),
    65→   self-hosted as the two gstatic subsets in `src/fonts/` — the SAME bytes
    66→   the live serves (`fonts.gstatic.com/s/vendsans/v1/…`, traced via
    67→   performance entries in Session 5). Session 1 misidentified it as
    68→   "Base44-hosted Wix Madefor" (the Wix faces are declared only in the
    69→   live's unused login-bundle css) and the wrong metrics (+2.4% glyph
    70→   width) drifted every text surface for four sessions. Never trust a
    71→   font's NAME — trace its bytes.
    72→6. **The reference ships INERT classes** — its markup carries utilities
    73→   its compiled css never emits (the pricing Pro card's `scale-[1.02]
    74→   md:scale-105` renders UNSCALED: `scale: none`, 540px at every width).
    75→   Match the RENDERED computed style, not the class string; v4 here WOULD
    76→   emit those utilities (540×1.05 = the old 567px D19 delta).
    77→7. **The reference is a moving target.** The live app at
    78→   `saas-company.base44.app` has been redeployed with different products
    79→   across this repo's history (the previous cycle cloned a PM workspace
    80→   called ORBITAL). Visual parity was re-measured against the CURRENT live
    81→   (dark NovaAI marketing site); the measurements live in
    82→   `Project_Architecture_Document.md` §5 and the e2e pins.
    83→8. **Rate limits are per-process.** Auth endpoints throttle 10
    84→   attempts/IP/15 min (in-memory `src/lib/rate-limit.ts`; override with
    85→   `AUTH_RATE_LIMIT_MAX` — the Playwright webServer pins 50 because the
    86→   suite's own ~10 UI sign-ins share one IP and one process with the
    87→   limiter; at the default they sat at EXACTLY the budget — Session 11
    88→   saw one extra signed-in spec trip a mid-suite 429 that broke an
    89→   unrelated pin).
    90→9. **Dependency overrides are load-bearing.** `package.json` pins
    91→   `overrides` for `braces`/`micromatch`/`fast-glob`/`deepmerge-ts` — the
    92→   patched transitive versions for advisories whose parents haven't shipped
    93→   fixes (the residual `braces` GHSA-vfj7-8cjw-p6xm covers every published
    94→   version; lint-toolchain-only — see the remediation plan F10). Never run
    95→   `npm audit fix --force` here: it would downgrade `eslint-config-next`
    96→   16→14 to silence a dev-time advisory.
    97→10. **`/dashboard` is session-gated** (`redirect("/login?from_url=/dashboard")`)
    98→   — expect 307 for anonymous requests; the smoke suite pins both the 307
    99→   and the cookie'd 200.
   100→11. **The reference ships TWO token blocks — `:root` and `.dark`.** The app
   101→   never mounts `.dark`, so `:root` is what renders: primary = hsl(267 100%
   102→   57%) = #8624ff, accent/electric-blue = hsl(220 100% 50%) = #0055ff, while
   103→   `violet` (the magenta used by text/border/bg-violet) = #d500ff. Session 1
   104→   read the `.dark` block and shipped the wrong primary/accent for two
   105→   sessions — the Session-3 audit fixed it (see
   106→   `docs/remediation-plan-session3.md` F1/F2).
   107→12. **Arbitrary aspect ratios use the SLASH (`aspect-[16/9]`), never the
   108→   colon spelling** — writing the ratio with a colon inside the brackets
   109→   emits the invalid `aspect-ratio: 16:9` into the compiled CSS and postcss
   110→   fails the whole build with an opaque `CssSyntaxError … Missed semicolon`
   111→   at a flattened column. Worse: Tailwind's scanner reads class candidates
   112→   from MARKDOWN too — documenting the colon spelling in a .md file breaks
   113→   the build just like using it in a component (docs/ is `@source not`-ed
   114→   in globals.css for exactly this reason; Session 4 hit both).
   115→13. **The reference's /login loads its OWN css bundle** (light `:root`, body
   116→   white + zinc-950 + the system font stack) — the login route swaps the
   117→   body theme via a route-scoped `<style>` in `login/page.tsx`; every other
   118→   route keeps the dark theme. Also: the reference's compiled `space-y-*`
   119→   puts the gap on the FOLLOWING sibling (v3-style) — v4's
   120→   margin-bottom-on-preceding is lost on inline labels (the login form)
   121→   AND is cancelled by the alternate-states' back-button `-mb-2`, so the
   122→   route style restores that pattern inside forms (`.space-y-1\.5`) and
   123→   the auth stack (`.auth-stack` / `.auth-stack-sm6`). The card's
   124→   ALTERNATE states (sign-up / forgot / reset-success) use a DIFFERENT
   125→   layout from the default: back-button + h2 + form, NO logo chip,
   126→   NO Google button, NO OR divider, and shadcn-style alert banners
   127→   (bg-red-50/70 / bg-green-50/70) rendered BETWEEN the last field and
   128→   the submit button — measured in Session 5, pinned by
   129→   `tests/e2e/login-states.spec.ts`.
   130→14. **The navbar is section-aware and never gains a background.** It is
   131→   `bg-transparent` at every scroll depth (no scrolled-glass bar); a
   132→   scroll-spy highlights the section in view (last section whose top passed
   133→   the ⅔ viewport line) and the chrome swaps to black variants while the
   134→   nav band overlaps `[data-nav-theme="light"]` sections (the white
   135→   features section). Pinned by `tests/e2e/navbar-behavior.spec.ts`.
   136→15. **The dashboard mockup LOOPS — never re-add the skeleton-wave shimmer,
   137→   and never trust a CSS-property census against a JS animation engine.**
   138→   The live pulses the ambient `-inset-32` glow (scale 1→1.15→1 + opacity
   139→   .3→.5→.3, 4s), the red chrome dot (scale 1→1.2→1, 2s), the four list
   140→   dots (same, staggered delay:i*.1), the under-glow (y 0→−12→0 + opacity
   141→   .3→.5→.3, 3s — a SIBLING of the card, unclipped, rendered UNCENTERED:
   142→   its framer transform kills the `-translate-x-1/2`, pinned via
   143→   `translate-none`), and the One-Platform mini-dashboard's skeleton
   144→   shapes (opacity pairs at 3s with delays) — reproduced as the measured
   145→   `animate-mockup-*`/`animate-skel-*` keyframes in globals.css. The list
   146→   dots keep their SOLID `bg-primary/80` fill (never re-add the
   147→   `skeleton-wave` shimmer: as an UNLAYERED class it overrides the layered
   148→   `bg-primary/80` utility). Session 4's "the mockup is completely
   149→   STATIC" census was an artifact: framer writes inline styles per frame,
   150→   so `animationName` reads `none` on an element that is mid-loop — survey
   151→   motion by sampling VALUES over time (see PAD §5.5 trap 16). The pricing
   152→   toggle defaults to ANNUAL (Pro $39/mo annual, $49/mo monthly — the $39
   153→   Session 1 read was the annual price).
   154→16. **Hover-state probes need REAL pointer events** (Session 6) — an
   155→   agent-browser `mouse move` reported `:hover` matching while no hover
   156→   utility applied (a false negative Playwright's real `page.mouse.move`
   157→   disproved — the Get Started pill's shimmer was working all along).
   158→   Related: the live's arrow slide renders v3 `transform: matrix(1,0,0,1,2,0)`
   159→   while v4 emits `translate: 2px` — compare RENDERED geometry, not the
   160→   property name.
   161→17. **The reference's `<head>` is per-route** (Session 6): content routes
   162→   ship og:title = the page title, description = "X on SAAS Company. …",
   163→   and og:url = canonical = the route (implemented here through
   164→   `src/lib/seo.ts` + per-page `routeMetadata` exports; `/og-image.png`
   165→   is the WORKING replacement for the live's dead og:image URL). Do NOT
   166→   re-add `theme-color` or `viewport-fit` — the live ships neither.
   167→18. **The live's mobile burger is pointer-blocked by its own empty toast
   168→   portal** (fixed top-0 z-[100], 390×32, pointer-events auto — a JS
   169→   click opens the live's menu, a real tap cannot; D32). The clone keeps
   170→   the WORKING burger; never "fix" it toward the live's broken state.
   171→19. **The reference's SPA bundle DOUBLES the tracking scale** (Session 7):
   172→   `tracking-wider` renders 0.1em and `tracking-widest` 0.2em on the live
   173→   — the overrides live in globals.css `@theme`
   174→   (`--tracking-wider`/`--tracking-widest`), while the live's LOGIN bundle
   175→   keeps the standard scale (pinned back in the login route's scoped
   176→   `<style>`). Never "simplify" either side — the divergence is the
   177→   reference's own two-bundle reality.
   178→20. **Breakpoint-mounted chrome needs a resize guard** (Session 7): the
   179→   mobile menu mounted below `md` and hidden above it kept its state (and
   180→   the body scroll-lock) alive when the viewport crossed 768 — the
   181→   `matchMedia("(min-width: 768px)")` close-on-match listener in
   182→   `navbar.tsx` is load-bearing for resize/rotate flows.
   183→21. **The scroll entrances are rAF-driven, NOT CSS transitions** (Session 8):
   184→   the reference uses framer-motion (per-frame inline opacity/transform
   185→   writes, easeOut cubic-bezier(0,0,0.58,1), per-element params); the
   186→   `Reveal` component re-implements it via `src/lib/motion.ts`. Never add
   187→   `transition-*` classes to entrance wrappers — on children that carry
   188→   their own `transition-colors` the cascade SNAPS the entrance and
   189→   corrupts the child's hover timing (the Session-8 F1 bug). The
   190→   per-element parameter table lives in `docs/remediation-plan-session8.md`.
   191→22. **v4 ships THREE more engine shifts beyond oklab** (Sessions 7–8): the
   192→   tracking scale (the live's config doubles the two widest steps —
   193→   `@theme --tracking-*`), the shadow-scale rename (v3 shadow-sm → v4
   194→   shadow-xs — pinned via `--shadow-sm`), and the line-height cascade
   195→   (v3's responsive `text-*` beats `leading-*`; v4's `--tw-leading` always
   196→   wins — pinned per-element via `--tw-leading: initial`). Survey the
   197→   ENGINE layer (computed values + the emitted rules), not just class
   198→   strings — every one of these hid from class-string parity for 6+
   199→   sessions.
   200→23. **v4's default palette is OKLCH-DEFINED — the roundtrip drifts from
   201→   v3's hex** (Session 9): up to 69 RGB units off (green-400; the stars'
   202→   yellow-400, the problem cards' reds, the avatar gradient endpoints,
   203→   every login slate drifted). The pins live in `globals.css` `@theme`
   204→   (`--color-<family>-<shade>: <v3 hex>` — 31 tokens). Never "simplify"
   205→   them back to v4 defaults, and never trust a color assertion that
   206→   accepts both spellings without comparing VALUES. Related v4
   207→   token-emission trap: `ring-ring` reads `--color-ring` (a legacy
   208→   `--ring` HSL variable is NOT the emission path — without the @theme
   209→   token the utility never emits and the ring falls back to currentColor),
   210→   and v4 emits ring-ring AFTER ring-slate-400, so elements carrying both
   211→   need the `input:focus:focus-visible` cascade nudge in the utilities
   212→   layer. The live also ships NO `::selection` rule (ours was an
   213→   invention, removed) and pins `/login` `html { overscroll-behavior-y:
   214→   none }` + a light `--border` (both reproduced route-scoped).
   215→24. **A JS animation engine is INVISIBLE to a CSS-property census**
   216→   (Session 10): framer-motion writes inline `transform`/`opacity` per
   217→   frame, so an element can be mid-loop while `getComputedStyle()
   218→   .animationName` reads `none` — the Session-4 "static mockup" verdict
   219→   shipped static for six sessions while the live pulsed eight loop
   220→   groups. Survey the LOOP layer by sampling computed VALUES across
   221→   multiple rounds after entrances settle AND by extracting the
   222→   `animate:{…}`/`transition:{…}` configs from the live's JS bundle.
   223→   Related: framer's inline transform REPLACES v3's `--tw-translate-*`
   224→   composition (the live's under-glow renders un-centered) — v4's
   225→   `translate` property is SEPARATE from `transform`, so reproducing that
   226→   geometry needs an explicit `translate-none` (PAD §5.5 trap 16).
   227→25. **A statically-prerendered CLIENT component cannot render route state
   228→   at SSR — and `usePathname()` settles to the INTERNAL route id on
   229→   404s** (Session 11): the not-found page shipped React #418 on EVERY
   230→   unknown route (the prerendered HTML quoted `"_not-found"` while the
   231→   hydration render carried the real URL — a text mismatch by
   232→   construction), and post-settle `usePathname()` returns `/_not-found`,
   233→   not the browser URL. The pattern: a `useSyncExternalStore` mount gate
   234→   (server snapshot false) reading `window.location.pathname` — pinned
   235→   by `tests/e2e/hydration.spec.ts`. Sweep the CONSOLE layer (pageerror)
   236→   on every route — a clean render can still ship a broken hydration.
   237→   Related Session-11 lessons: sample TRANSITIONING properties to
   238→   settled (the ring pin's fixed-200ms mid-flight samples + its
   239→   blind-Tab×4 focus misses made the gate itself flaky — poll, and
   240→   tab-until-focused), and alpha composites through ANCESTOR opacity
   241→   (the paused cards' `opacity-80` turned `text-white/50` into effective
   242→   white/40 — audit the EFFECTIVE alpha, not the class; the clone-only
   243→   axe violations on `/`, `/faq`, and the 404 are LIVE-PARITY — D63,
   244→   not bugs to fix).
   245→26. **React Float auto-preloads eager `<img>`s rendered in the SSR shell —
   246→   and the Next.js router's RSC prefetch INJECTS those head links into
   247→   every route that links to the page** (Session 12): the Gasparyan
   248→   logo's automatic `<link rel="preload" as="image">` traveled from the
   249→   landing into /faq, /privacy, /terms, /accessibility, /refund-policy,
   250→   and /dashboard (the navbar's logo `<Link href="/">` prefetch), where
   251→   the image never renders — a console "preloaded but not used" warning
   252→   + a wasted fetch on six routes. `loading="lazy"` suppresses the
   253→   emission entirely (pinned by `tests/e2e/resource-hygiene.spec.ts` +
   254→   the smoke static-HTML pin). Audit `<link rel="preload">` on EVERY
   255→   route, not just the page that owns the resource. Related Session-12
   256→   lessons: fault-inject the network (`page.route(...abort())`) before
   257→   trusting a happy path — the dashboard's pause/delete/sign-out carried
   258→   NO catch and surfaced `TypeError: Failed to fetch` pageerrors with
   259→   zero user feedback (now banners — `tests/e2e/resilience.spec.ts`);
   260→   and before believing a mid-verification regression, verify the server
   261→   serves the CURRENT build — compare the served HTML's CSS chunk
   262→   filename against `.next/standalone/.next/static/chunks/` on disk (a
   263→   ZOMBIE server on :3000 serving a stale build whose CSS chunks were
   264→   deleted renders UNSTYLED: links concatenate in innerText and word
   265→   parity collapses; the Playwright/smoke suites are immune — they boot
   266→   their own servers).
   267→27. **A 401 is not a network fault — failure CLASSES need distinct UI
   268→   contracts; and ship `error.tsx`/`global-error.tsx` before you need
   269→   them** (Session 13): a cookie-expired session makes every dashboard
   270→   mutation 401 — and "Try again." banners LIE (each retry 401s forever).
   271→   The honest contract is the server gate's own: redirect to
   272→   `/login?from_url=/dashboard` (the `apiFetch` wrapper in
   273→   `dashboard-app.tsx`; pinned pairwise against the abort-banner class
   274→   by `tests/e2e/session-lifecycle.spec.ts`). Likewise a render fault
   275→   (malformed API data — a row with `runs: null` passes the
   276→   `Array.isArray` envelope guard and crashes the article template) must
   277→   surface the BRANDED boundary (`src/app/error.tsx`), never Next.js's
   278→   default "This page couldn't load" page — the app loses its identity
   279→   exactly when the user is already having a bad day (pinned by
   280→   `tests/e2e/error-boundary.spec.ts`; pin the boundary with a
   281→   route-fulfilled contract violation, not a synthetic throw). Related:
   282→   Escape-closing the mobile menu must RETURN FOCUS to the burger
   283→   (`burgerRef`) — the focused link unmounts with the panel and
   284→   `activeElement` falls to `body`, stranding keyboard users (WCAG
   285→   2.4.3).
   286→28. **Audit REACHABILITY, not just behavior — and success is a
   287→   message class too** (Session 14): grep every API route for a UI
   288→   consumer BEFORE calling it a shipped feature — `POST /api/demo`
   289→   shipped complete (validation + rate limit + model) with ZERO
   290→   consumers: dead code dressed as a superset. A feature unreachable
   291→   from any URL is not a feature (`/demo` is its front half — D73).
   292→   Likewise `/login` must redirect ALREADY-authenticated visitors to
   293→   the workspace (D74) — and NOTE: any script or spec that signs in and
   294→   then revisits `/login` will hit the redirect (the screenshot
   295→   refresh script's re-sign-in blocks had to navigate to `/dashboard`
   296→   directly). And successful mutations need STATUS MESSAGES (WCAG
   297→   4.1.3): errors alert (`role="alert"`), successes confirm politely
   298→   (a sr-only `role="status"` `aria-live="polite"` region — D75) —
   299→   pre-fix the dashboard had zero live regions; a screen-reader user's
   300→   actions changed the stats in total silence. Related: computed
   301→   `animation-duration` for sub-millisecond values serializes in
   302→   SCIENTIFIC NOTATION ("1e-05s" for the authored 0.01ms clamp) —
   303→   compare parsed milliseconds, never the string; and the browser's
   304→   own 404-document resource log is inherent noise on BOTH sides (the
   305→   live's 404 ships two 401s — the D68 parity family).
   306→29. **Guard WHERE a user-controlled redirect can ship the browser — and
   307→   a hang is not a failure** (Session 15): any query param that becomes
   308→   a post-auth `router.push` target is an OPEN REDIRECT (CWE-601) until
   309→   proven otherwise — `/login?from_url=https://evil.example/phish`
   310→   genuinely shipped the just-authenticated browser off-site (the
   311→   network log carried `?_rsc=…`). The guard (`safeRedirectPath`):
   312→   prefix checks + a WHATWG dummy-origin re-parse; only same-site
   313→   absolute paths survive (D76). Likewise the HANG class: ADR-004's
   314→   degrade-not-fail covers SDK FAILURES, not hangs — a black-holed
   315→   `await` blocks the request forever with the UI's busy guard
   316→   engaged; every external await needs a timeout that RESOLVES with
   317→   the fallback (a hang is a degrade condition; a rejection still
   318→   propagates — D78). And survey the DOCS-TRUTH layer: README promised
   319→   `Retry-After` on 429s that no route emitted (D79) — pin what the
   320→   docs claim. Related traps this session: the Bash output layer can
   321→   SWALLOW `[m`-style character pairs from file contents (a
   322→   `const [mode, setMode]` line DISPLAYED as `const ode, setMode]` —
   323→   looked like a syntax error while tsc/esbuild/build were all green;
   324→   hex-dump before believing a "corrupt" file), and the
   325→   chunk-against-disk zombie check is BLIND when only JS changed (the
   326→   CSS chunk name is content-hashed and the CSS was untouched — the
   327→   old process served fresh static HTML from disk with its own stale
   328→   hydrated JS; when ps//proc are process-blind, move the survey to a
   329→   FRESH PORT with a fresh boot instead of trusting a reboot).
   330→30. **Rate-limit the expensive endpoint, not just the sensitive ones —
   331→   and probe authenticated APIs through the PAGE, not `page.request`**
   332→   (Session 16): auth/newsletter/demo were all limited while
   333→   `/api/workflows/generate` — the ONLY endpoint that costs real money
   334→   per call — was unlimited (the probe drove 15/15 rapid authenticated
   335→   POSTs all 200 in 8.1s). The fix keys the bucket PER-USER
   336→   (`gen:${userId}` — the route is authenticated; an IP-keyed bucket
   337→   would make a shared-egress office share one abuser's budget),
   338→   overrides via `GENERATE_RATE_LIMIT_MAX` (the AUTH_RATE_LIMIT_MAX
   339→   pattern), and keeps the CLIENT contract untouched: compose()'s
   340→   `genRes.ok` degrade means a 429 still creates the template workflow
   341→   — the feature never hard-fails, the limiter only caps the LLM spend
   342→   (D80). The envelope also now carries `Cache-Control: private,
   343→   no-store` at the ok()/fail() seam (Next protects dynamic PAGES with
   344→   no-store but NOT route-handler JSON — D81), and
   345→   `poweredByHeader: false` drops the X-Powered-By banner the live
   346→   doesn't ship (D82). Survey-tooling traps: Playwright's
   347→   `page.request` (APIRequestContext) REFUSES to send `Secure` cookies
   348→   over plain http while Chromium page navigations treat 127.0.0.1 as
   349→   trustworthy and DO send them — authenticated API probing must go
   350→   through in-page fetches after a navigation; and after an API

   653→  honestly at >100 rows — D106) with the pure `rankByRuns()` fallback

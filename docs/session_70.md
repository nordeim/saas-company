## The normalization contract (the twice-deferred piece, now designed)

- **Property scope:** the semantic 14-property whitelist (color, background-color, font-family/size/weight/style, line-height, letter-spacing, text-transform, text-align, text-decoration-line, border-top-color/width, border-top-left-radius) — EXCLUDING the animation-touched properties (opacity/transform/filter — framer writes them per frame, gotchas 15/24) and the layout/positioning engine (display/position/insets — structural wrappers differ by construction, the D125 family).
- **Color canonicalization (gotcha 4 at fleet scale):** rgb/rgba/hex/hsl/oklab/oklch/color(srgb) all parse to `[r,g,b,a]` tuples and compare with a 2-unit + 0.02-alpha tolerance. Rendering-identical spellings compare EQUAL by construction; never "fix" the CSS to chase byte-parity.
- **Length canonicalization:** px floats with a 0.5px tolerance, PLUS the FULL-radius equivalence class — any two radii ≥ 1000px compare equal (v3's `rounded-full` 9999px ≡ v4's `calc(infinity × 1px)` 33554432px, geometrically identical for any real element), and the float parser accepts Chromium's SCIENTIFIC NOTATION serialization ("3.35544e+07px").
- **The element anchor:** the k-th text-bearing element (a direct text-node child, skipping script/style/noscript/template — the word-parity column's anchor class) per route, with an element-count guard that fails loudly rather than mis-pairing silently.
- **The rendered-ness check:** `getClientRects().length === 0` skips non-rendered elements — a child inside a display:none SUBTREE still computes its OWN display ("block"), so the computed-display check the first authoring used read 7 false element-count drifts on the mounted-hidden elements (the box check is the offsetParent trap's safe twin: it works for fixed-position chrome too).
- **At-rest discipline:** the scroll-through pass (gotcha 44) runs before collection on both sides.

## The aria-* vocabulary extension (the ninth column's growth)

The shared aria-* attributes joined the VALUE column with radix-tolerant ID-reference normalization — and the first run caught a REAL functional gap, the opposite direction from the expected library-structure noise: **every aria-controls reference on the clone was DANGLING at rest** (the FAQ panels AND the burger's mobile-menu were conditionally rendered — unmounted when closed) where the live's Radix regions are MOUNTED-HIDDEN (every `radix-:rN:` id resolves to a role=region element with hidden=true). The stale Session-4 record ("Radix unmounts closed content, which is why the live's collapsed answers never appear in its HTML") described the pre-hydration SPA shell, not the rendered DOM — the collapsed answers never appear in the live's innerText because its panels are display:none-HIDDEN, not absent.

The fix (D132): the FAQ panels and the mobile-menu mount hidden at rest — the `hidden` attribute (display:none) keeps the answers out of innerText exactly like the live (the S4 word-parity 0.6052 artifact was CSS-COLLAPSED panels, which innerText includes; display:none it does not), and every aria-controls reference resolves. The accordion's `--radix-accordion-content-height` var moved from a mount-time ref to a `useLayoutEffect` keyed on open — a ref through display:none reads scrollHeight 0, and the layout effect runs after the hidden flip but before paint, so the accordion-down keyframe reads the true height from its first frame.

The registry's VALUE layer gained the **id-refs rule type** (`DOM_VALUE_RULES`, now five entries): aria-controls and aria-labelledby compare the FUNCTIONAL contract — every reference must RESOLVE to a mounted element in its own document at rest (a dangling aria-controls is a real a11y defect; a resolved one in a different namespace is not) — while aria-expanded is values-only (the clone's burger the one extra carrier, all "false" at rest; gotcha 47).
